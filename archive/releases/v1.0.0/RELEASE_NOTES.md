# Data Release v1.0.0 — permitted-data release

**The Kai Tak Historical Research Archive**

Historical Geography, Aviation Evidence, Flight Dynamics and Mathematical Reconstructions of Hong Kong's Kai Tak Airport.

This is the first archive-version series, independent of paper/model versions and the three retained 2026-10-13 GitHub tags. GitHub publication was authorized on 2026-10-13. No DOI or new original-work license grant has been issued.

The frozen catalogue describes 3,268 canonical artifacts in 44 datasets and nine stable collections. Five complete, independently restorable data bundles contain 418 verified-permitted files (1,305,783,427 uncompressed bytes): acquired map ZIPs/full DAP-L0 photographs, source-linked modern structure data, terrain/geospatial material, NOAA observations and registered raster derivatives. See [master manifest](manifest.json), [checksums](SHA256SUMS) and the exact collection manifests. Collections 04, 07, 08 and 09 are catalogue-only in this release.

The 2,850 other catalogue artifacts are explicit exceptions, not promised downloads. Many exist in the inherited Git source or old releases, but historic publication is not evidence of a new redistribution license. Original-work grant decisions, CAD/AIS/Boeing permission, HKMS historical-index/preview rights and missing exact lineage remain unresolved. New metadata/code/support files are published with existing rights retained, not newly open-licensed.

Modern building data are not complete 1993 geometry. Photo-index rows are not full frames. Registered raster outputs have pinned source/output hashes, not independently validated survey accuracy. Synthetic trajectories establish neither complete historical obstacle clearance nor global optimality or operational safety. Seven explicitly invalidated analytical JSON results are identified in metadata without changing original bytes. Three inherited v1 evidence-manifest discrepancies and historical source-version gaps are retained in the audit.

For verified execution evidence and blockers use the [publication-readiness report](../../PUBLICATION_READINESS.md). Corrections before publication remain candidate revisions; once accepted/published, any changed data require a new semantic version with retained prior bytes and correction notes.

Private correspondence, enquiry transport/session data and the private Git-history backup are excluded. Later accepted white-paper v3/v4 files are preserved unchanged on main, outside this fixed data-catalogue boundary.
